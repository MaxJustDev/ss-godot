Standalone Project Godot 4.3+ MIT License (proposed) Distribution: Asset Library + GitHub release Upstream: github.com/SaiGame-studio/ss-unity

0. Mục tiêu & Phạm vi

Goal

Port toàn bộ SaiGame Services SDK v0.2.40d từ Unity C# sang Godot 4 GDScript, đóng gói dạng plugin addon, publish lên Godot Asset Library để bất kỳ project Godot nào cũng import 1-click và dùng.

Non-goals (việc KHÔNG làm)

  • Không thay đổi backend SaiGame (giữ nguyên api.saigame.studio).
  • Không thay đổi protocol REST hiện có — port tương đương 1-1.
  • Không gắn business logic của game vào — chỉ làm SDK pure.
  • Không hỗ trợ Unity feature không có ở Godot (vd: ScriptableObject inspector custom — sẽ dùng Resource).

Lý do tách project riêng

  • Reusable: bất kỳ project Godot nào dùng SaiGame backend đều import được.
  • Versioning độc lập: SDK update không buộc game update.
  • Cộng đồng: đóng góp / bug report tập trung 1 repo.
  • Maintenance: bug fix 1 nơi, hưởng ở mọi project.
  • Showcase: portfolio open source. SaiGame studio có thể đỡ chính thức hóa.

3. plugin.cfg — Manifest

[plugin]

name="SaiGame Services SDK"
description="REST client SDK for SaiGame backend. Provides Auth, GamerProgress, Inventory, Quest, Shop, Leaderboard, Battle Sessions, Mailbox, Journey services."
author="<your-name>"
version="0.1.0"
script="plugin.gd"

plugin.gd — Entry point (đăng ký autoload)

@tool
extends EditorPlugin

const AUTOLOAD_NAME = "SaiServer"
const AUTOLOAD_PATH = "res://addons/sai_services/core/sai_server.gd"

func _enter_tree() -> void:
    add_autoload_singleton(AUTOLOAD_NAME, AUTOLOAD_PATH)

func _exit_tree() -> void:
    remove_autoload_singleton(AUTOLOAD_NAME)

User chỉ cần Enable plugin trong Project Settings → Plugins → autoload SaiServer tự xuất hiện. Không cần config thủ công.

4. Design Principles (Godot-idiomatic)

  • Signal > callback: thay vì Action<string> onSuccess, dùng signal Godot. Mỗi service emit success/failed signal.
  • async/await thay coroutine: tất cả API call return Dictionary, dùng await.
  • Resource cho DTO: Plain Dictionary cho JSON nhanh. Resource typed cho field cần serialize/inspect.
  • Autoload singleton: SaiServer autoload duy nhất, sub-services là Node con của nó hoặc lazy-loaded.
  • Snake case: convention GDScript. Method get_progress() chứ không GetProgress().
  • Zero dependency: không import thư viện ngoài (HTTP/JSON/crypto đều dùng built-in Godot).
  • Type hints: dùng full GDScript static typing — func login(username: String) -> void.
  • Error code thay exception: GDScript thiếu exception → return Dictionary {"success": bool, "error": String, "data": Variant}.

6. Endpoint discovery — pre-port

Trước khi port code, phải có danh sách endpoint chính xác từ Unity SDK gốc.

3 cách discovery

  1. Static analysis Unity repo
    git clone ss-unity && grep -rn "GetRequest\|PostRequest\|PutRequest\|PatchRequest\|DeleteRequest" Assets/SaiGame/Scripts/
    → Liệt kê tất cả endpoint string literals trong codebase.
  2. Runtime capture
    Chạy demo Unity scene với mitmproxy man-in-middle → log toàn bộ request/response. Cách tốt nhất để có payload thật.
  3. Hỏi SaiGame
    Yêu cầu OpenAPI/Swagger spec hoặc Postman collection. Nếu họ có → skip cả 2 bước trên.

Output yêu cầu

  • Mandatory Tất cả public API có docstring GDScript (## comment).
  • Mandatory Static typing đầy đủ — không có Variant không cần thiết.
  • Mandatory README quick start chạy được trong 5 phút.
  • Mandatory Demo project working out-of-box.
  • Mandatory LICENSE file (MIT đề xuất).
  • Mandatory CHANGELOG semver.
  • Strong CI: lint (gdtoolkit), test (GUT framework).
  • Strong Coverage >= 70% trên core (sai_server, auth, AES).
  • Nice Custom EditorInspectorPlugin cho SaiServer (debug button: ping API, manual login).
  • Nice Sample data set local mock server (Python flask) để test offline.

9. Godot Asset Library — submit checklist

Theo godotengine.org/asset-library hướng dẫn:

  1. Repo public trên GitHub/GitLab/Bitbucket.
  2. Tag commit SemVer: v0.1.0.
  3. License OSI-approved trong root LICENSE.
  4. README có screenshot/preview (recommended).
  5. Cấu trúc addons/<name>/ chuẩn để Godot biết đây là plugin.
  6. Đăng ký account Godot Asset Library.
  7. Submit form: name, description, category, version compat, download URL (GitHub release zip).
  8. Maintain: mỗi version mới tag + submit "Update" lên Asset Library.

Categories phù hợp

  • Tools — phổ biến nhất cho SDK/plugin
  • Scripts — nếu chỉ code, không tool editor
  • Có thể submit cả 2 category nếu phù hợp.

10. Versioning & Release

SemVer

  • Major: breaking API change (rename method, đổi signature signal).
  • Minor: thêm module mới, thêm method.
  • Patch: bug fix.

Sync với Unity upstream

Unity ss-unity tag version riêng (v0.2.40d). Godot port giữ SemVer riêng nhưng note "tracks ss-unity v0.2.40d" trong CHANGELOG. Lý do: API Godot có thể idiomatic khác Unity, không phải port 1-1 string.

Release process

  1. PR merge vào main.
  2. Bump version trong plugin.cfg + CHANGELOG.md.
  3. git tag v0.X.Y + push.
  4. GitHub Action release.yml auto-zip addons/sai_services/ + tạo release.
  5. Submit "Update" trên Asset Library với link release.

12. Tích hợp ngược vào game Checkmate Hold'em

Sau khi ss-godot live trên Asset Library, game chính chỉ cần:

Steps (5 phút)

  1. Trong project Godot: AssetLib tab → search "SaiGame Services SDK" → Download → Install.
  2. Project Settings → Plugins → Enable SaiGame Services SDK.
  3. Autoload SaiServer tự xuất hiện ở Project Settings → Autoload.
  4. Set game_id trong inspector của SaiServer scene (hoặc Project Settings).
  5. Code: 
    # scripts/main_menu.gd
extends Control

func _on_login_pressed() -> void:
    var auth: SaiAuth = SaiServer.get_node("SaiAuth")
    auth.login_success.connect(_on_login_ok)
    auth.login_failed.connect(_on_login_err)
    auth.login(username_field.text, password_field.text)

func _on_login_ok(user: Dictionary) -> void:
    print("Welcome %s" % user.username)
    get_tree().change_scene_to_file("res://scenes/lobby.tscn")

func _on_login_err(error: String) -> void:
    show_toast("Login failed: %s" % error)

Tách project = upgrade SDK đơn giản: AssetLib có update → bấm Update → restart. Không động chạm game code.

13. Communication với SaiGame Studio

Trước khi bắt đầu port, nên liên hệ SaiGame studio để:

  1. Xác nhận license: ss-unity license gì? MIT? Apache? Có cho phép port + publish derivative không?
  2. Xin OpenAPI spec: tiết kiệm tuần SDK-M0.
  3. Xin credentials dev/staging: GAME_ID + test account để dev.
  4. Hỏi roadmap chính thức: nếu họ định làm Godot SDK official → có thể cộng tác / contribute thay vì fork.
  5. Naming convention: dùng tên "SaiGame Services SDK" hay tên khác để tránh trademark conflict?

Template email/issue mẫu:

Subject: [Godot port] SaiGame Services SDK — collaboration inquiry

Hi SaiGame team,

I'm planning to port your Unity SDK (ss-unity v0.2.40d) to Godot 4 and publish
it on the Godot Asset Library as an open-source addon. Before I start, I'd
like to clarify:

1. Is the current ss-unity license compatible with creating a derivative
   work for Godot? (I'll use MIT for the Godot port if acceptable.)
2. Do you have an OpenAPI/Swagger spec or Postman collection I can use?
3. Could I get dev/staging credentials to test against?
4. Would you be interested in adopting the Godot port as an official
   side-project, or prefer I keep it as a community port?

Repo plan: github.com/<my-handle>/ss-godot
License plan: MIT (open to discussion)

Happy to credit SaiGame studio as upstream and link back from the README.

Thanks!
